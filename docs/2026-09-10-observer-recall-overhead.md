### 召回：达到了平均目标，但需要支付查询代价

全量 1,183,514×100 GloVe、1792MB、2 worker，按预登记顺序评估：

| 构建参数 m / ef_construction | 构建 s（单次） | 容器峰值 MiB | spill | 调参最高 Recall@10 |
|---|---:|---:|---|---:|
| 16 / 64 | 151.284 | 3573.4 | 无 | 93.15%（ef=1000），未达标 |
| 16 / 128 | 249.894 | 3538.6 | 无 | 95.35%（ef=1000），选中 |

第二档的小规模预检通过后才执行全量；选中后不再尝试第三档，未超出两个全量
构建与一个预检。查询配置按调参集选择后锁定，新 1000 查询只用来验证，不回流：

| 同一最终索引的 ef_search | 验证平均 Recall@10 | p50 ms | p95 ms |
|---:|---:|---:|---:|
| 40 | 71.09% | 0.453 | 0.842 |
| 400 | 91.13% | 3.740 | 7.127 |
| 1000（选中） | 95.47% | 28.998 | 44.945 |

可用结论：在这份数据和固定协议下，增加建图质量并扩大搜索范围，得到平均召回
达到 95% 的候选。相对于最终索引 ef=400，召回增加 **4.34 个百分点**，查询
中位耗时约 **7.75 倍**。它不是“无代价修好召回”，也不是业务最优参数。
本轮没有业务延迟预算；平均目标达成不保证每个 query 达标，选中配置中最低
单查询 Recall@10 仍为 30%。它也不构成总体平均召回不低于95%的统计置信保证。
新旧轮次的查询集/图不同，不直接相减归因。

原始证据：[正式报告与图](../experiments/hnsw_build/results/20260910T074253Z-bounded-recall/report.md)、
[选参锁定记录](../experiments/hnsw_build/results/20260910T074253Z-bounded-recall/selection-before-validation.json)。
两档各 3600 条调参测量，最终 9000 条验证测量，共 16,200 条；验证独立样本
仍只有 1000 个。构建和查询的临时库已清理，开销实验使用另外的新库。

### 开销：部分场景有支持，默认关闭路径仍有风险

[正式报告](../experiments/hnsw_build/results/20260910T075739Z-bounded-overhead/report.md)
完成四场景各 12 个块，共 **192 次正式构建、96 次预热**，全部原始测量保留。
48 次带观察的构建均实际采到进度；96 个开销临时环境全部清理。

下表每格为“配对变化中位数 / 总体中位比值的单侧上界”，不是最坏运行开销。
上界基于独立块假设、逐项至少95%覆盖（本样本数实际约98.1%），不作联合保证。

| 场景 | 新版关闭 / 旧版 | 新版开启 / 新版关闭 | 开启并观察 / 仅开启 |
|---|---:|---:|---:|
| 串行、无 spill | +0.66% / +24.13% | −0.11% / +9.34% | −0.89% / +5.38% |
| 串行、spill | +8.04% / +10.85% | −4.71% / −0.04% | +0.95% / +4.43% |
| 2-worker、无 spill | +25.05% / +52.74% | −3.31% / +21.02% | +3.66% / +16.29% |
| 2-worker、spill | +10.11% / +13.60% | −5.72% / +0.39% | +1.13% / +4.30% |

- 两个 spill 场景中，**开启计时的增量**和**增加1秒观察的增量**，分别有支持
  低于5%参考线的证据：12项比较中4项支持，8项未建立。负变化不当作功能提速。
- 新版关闭/旧版的四项均未建立低于5%的保证。尤其 +8.04%、+25.05%、+10.11%
  的中位变化需要保留为性能风险信号，不能笼统写“没有回归”。
- 当前结果尚不能将变慢精确归因到 C 代码：跨镜像比较、缓存/WAL 状态、宿主
  波动与并行图拓扑仍可能影响结果。串行索引字节数在同场景下保持一致，但
  相同大小本身不证明所有状态完全相同。
- 已只读核对实际镜像、worker/spill、计时摘要与源码指纹；关闭组没有内部计时
  摘要，源码中的时钟读取受开关保护。这些检查不能替代默认关闭成本的定位。

因此，**本轮实现与测量完成，默认关闭路径的性能验收仍未关闭**。下一步应先
针对该信号做小范围定位：核对两镜像构建输入和参数，检查同会话执行位置效应，
再在预先固定的新协议中复现；只有可归因到实现的问题才修改 C 并重新回归。
本轮没有继续扩参、重新编译镜像或为得到更好结果重跑预算。

## 预先固定的边界

1. **只读观察**：独立入口，通过明确指定的 libpq service 和 PID 观察 PG18
   当前数据库的构建任务。只读取固定系统视图，无业务表扫描、建表、取消后端、
   文件读取或提权。只读短事务，1 秒默认采样，有超时与时间上限。缺权限、途中
   接入、任务变化或消失都显式标记；消失不等于成功。采样不是精确计时；可选
   本地日志仅作为独立证据，不将另一会话的 NOTICE 假装成实时可读取字段。
2. **召回**：新建一轮全量 GloVe，固定 2 worker、1792MB、正常 runtime，图拓扑
   不固定。调参沿用原 200 个 query；独立验证取原 seed 排列的第 1201–2200 个，
   与历史 200+1000 不重叠。候选构建最多 (m,efc)=(16,64)/(16,128)/(32,128)，
   按顺序，只在调参未达标时进入下一项；后两项先做 100k 内存预检。搜索候选
   ef=40/100/200/400/800/1000，每项三次暖服务器计时，目标 mean Recall@10≥.95。
   选择首个构建配置下最小达标 ef；仅最终选定配置（或全部未达标时最后配置的
   上限）访问新验证集。验证未达标不反向重选。保留同索引 ef=40/400 作成本参考。
   每次构建最多 30 分钟，容器 6GiB、无额外 swap，不增加 DSM 或宿主资源上限。
3. **开销**：全部重负载实验串行。合成 20k×32、m16/efc64，串行/2-worker 与
   高内存128MB/低内存1MB或4MB，共四场景。正式每场景固定 12 个独立环境块；
   每块各旧/新镜像预热一次，正式测旧版关闭、新版关闭、新版开启、新版开启并
   以1秒间隔观察。旧/新顺序交替，新版三条件轮换；不依据结果追加次数。
   比较三种配对比：新版关闭/旧版关闭、开启/关闭、观察/不观察。主指标为完整
   SQL 调用经过时间，不能拿内部计时测自身开销。串行使用既有 seed42 测试镜像；
   并行拓扑仍受调度影响，单独报告。参考线5%不是官方标准；使用配对比值中位数
   的分布无关单侧至少95%上置信界（按二项分布选择顺序统计量）；不足则结论为
   不确定。分别判定每场景，不把某一场景通过说成全部通过或生产保证。

## 读结果前先分清的口径

- 开销实验中的“旧版”是已有阶段/DETAIL 诊断、尚无新增内部计时的候选；“新版”
  是 9/6 内部计时候选。它比较的是**本次计时增强的增量成本**，不是整套诊断
  改动相对于原版 pgvector 的总开销。两者使用已记录的 seed42 测试镜像。
- 同一台 Mac 上的新一轮时间不能与 9/9 的单次数字当作算法加速对照。全量
  召回本轮每种配置仅构建一次；主要结论是实际命中率与查询代价，而非构建
  时间显著性。旧六次内存实验仍是那条内存对照结论的证据。
- “采到进度”只证明有实际观察，不保证每个短阶段被捕获。所有观察报告中的
  等待次数都是样本数，不换算成精确等待时长。
- 真实业务连接、业务 SLA 和维护者 Review 都尚未验证；公开词向量数据不是
  金融/医疗业务数据，也不是腾讯指定的“官方数据集”。
