# OpenTenBase 项目二需求复核与续作留痕

## 本页用途

本页以启动 PPT、会议逐字稿和可运行证据为依据，记录当前候选已经满足、部分
满足和尚未满足的要求，并作为后续补齐工作的验收清单。计划、代码和测试必须
分开记账；没有运行证据的项目不得标为完成。

## 需求来源与解释

- 启动 PPT 第 3、6、7、11、12 页：统一环境、项目二原文、诊断维度、五步
  验收和汇报节奏；
- 会议逐字稿 `00:03:03`、`00:08:37—00:10:53`、`00:13:53—00:14:49`；
- 逐字稿中的“通用 benchmark”属于项目一，“尽量使用官方数据集”属于项目三；
  项目二没有指定某个官方数据集，也没有要求必须使用外部数据集；
- 项目二若补低召回风险，可以自愿采用带 ground truth 的公开标准数据集，但
  必须写成“公开标准数据集”，不能写成“OpenTenBase 官方指定数据集”。

## 续作顺序与验收

### P0：Recall@K 与参数诊断

- 保持现有 C 补丁冻结，优先扩展独立实验工具；
- 用精确扫描 Top-K 作为 ground truth，与 HNSW Top-K 比较；
- 阈值必须由实验操作者显式传入并标明为本轮口径，不制造“官方/通用合格阈值”；
- 至少证明一个低 `ef_search` 配置触发风险，一个提高后的配置改善召回；
- 输出问题、原因、调整方法和验证方式。

### P1：内存规模关系与异常场景

- 一次只改变行数、维度或 `m`，记录构建时间、近似内存、索引大小与 spill；
- 优先使用确定性且不危害宿主机的异常场景；不主动制造宿主 OOM；
- 把已有 upstream 测试与新增项目证据分开列出，避免重复冒充贡献。

### P1：较大规模验证

- 按 `100k → 300k → 500k → 条件允许时 1M` 逐级预检；
- 性能实验继续使用同一 Debian ARM64 Docker 环境，CentOS 只承担兼容性；
- 不能稳定完成 1M 时，报告实际最大规模，不外推为生产规模。

### P2：Review 与交付

- 先独立检查 4 文件 diff，再按负责人确认的目录做最终 clean rebuild；
- 用户明确开始交付后，才创建 commit、push 或 PR；
- 每次阶段汇报固定写“完成情况、验证结果、下一步计划”。

## 工作记录

### 2026-09-03｜检查点 A：需求复核与续作启动

- 状态：完成需求复核；续作代码尚未开始；
- 结论：当前候选已完整闭环“构建慢/低内存 spill/进度观测”，但项目二整体仍
  缺低召回、完整参数建议、内存规模关系、异常证据索引和正式 PR；
- 数据口径：项目二没有被指定某个“官方数据集”；现有固定 seed 合成数据继续
  用于构建控制实验，公开标准数据集只作为召回补充候选；
- 范围约束：不进入 IVFFlat、图查询、分布式、LLM 诊断或通用内存预测模型；
- 下一步：设计并单元测试独立 Recall@K/参数诊断模块。

### 2026-09-03｜检查点 B：Recall@K 与参数诊断完成

- 新增可选 Recall@K：固定 seed 独立 holdout、Exact `Seq Scan` ground truth、
  逐查询 HNSW 计划验证、服务器侧 `EXPLAIN ANALYZE` 执行时间；
- 首次表内查询烟测暴露自身过滤伪影，保留结果但不采用，改为独立 holdout；
- 50k×64 固定 topology 参数实验 14 次全部通过，7 组构建参数、
  `ef_search=10–320`；两个关键扩展曲线各重复 3 次；
- 本轮 `0.95` 明确为实验协议，不是官方或通用阈值；
- 证据：[[2026-09-03-hnsw-parameter-diagnostics]]。

### 2026-09-03｜检查点 C：内存规模与 1M 实跑完成

- 固定 64 维、`m=16/ef_construction=64`，按 25k→50k→100k→300k→500k→1M
  逐级运行；全部无 spill、阶段单调且查询使用 HNSW；
- 1M×64 统一 0.2 秒采样的实跑构建 `247.056s`，测试宏图内存 `925MiB`，索引
  `570,105,856` 字节；
- 另补 32/64/128 维与 `m=8/16/32` 控制变量，共 10 个独立 scale run；
- 基于向下量化到整 MiB 的测试宏值，描述性固定配置斜率约
  `970 bytes/row`，明确禁止跨配置外推；
- 证据：[[2026-09-03-hnsw-memory-scale]]。

### 2026-09-03｜检查点 D：异常证据矩阵完成

- 映射空表/NULL、非法参数、维度边界、重复向量、插入/VACUUM、过滤、WAL 与
  串行/并行/spill 召回的上游测试和 OpenTenBase 通过证据；
- 单列本项目新增的 045 专项 TAP、低内存诊断、低召回参数闭环和 1M 边界；
- 工具参数、协议一致性、重复输入与并行 safety margin 测试补齐后，本地工具
  单元测试 28/28；
- 证据：[[2026-09-03-hnsw-anomaly-matrix]]。

### 2026-09-04｜检查点 E：证据协议与冻结快照审查

- 将 300k、500k、1M 行数点按统一 0.2 秒采样重跑；三次均通过、无 spill、
  阶段单调且查询使用 HNSW，图内存与索引字节和旧运行完全一致；正式 1M 时间
  更新为 `247.056s`，旧 0.5/1.0 秒结果只作方法修正留痕；
- 参数汇总器新增采样间隔、宿主/版本、距离/分布、镜像与 checkout 身份一致性

- 最终 r4 小型并行 spill 烟测验证 Exact `Seq Scan`、HNSW、1MiB safety margin
  解释、Python 版本与 `run.py`/`recall.py`/Compose 内容哈希；
- 只读交叉审查没有发现 C 并发或生命周期 P0/P1；同时主动记录历史限制：正式
  14 次参数运行未序列化当时 Python 工具哈希/工作负载字段，宿主 checkout 哈希
