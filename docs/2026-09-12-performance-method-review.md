# HNSW 诊断开销测量方法 Review 与新固定协议

本页在新正式数据产生前写定。用户本轮明确要求完成开发与本地验证，已接电，
并确认没有业务数据库、使用现有本地环境；提交与负责人确认仍留到开发收尾之后。
本人 Review 按用户表述记为“已基本理解”，不冒充维护者接收或逐条代码审查通过。

## 审查结论

1. 旧 A/A 比较的是同一候选关闭计时的两个实例。它不能估计相对未修改
   pgvector 的诊断成本，更不能单凭失败认定 C 存在性能回归。
2. 旧 A/A 的 n=8、经验 p90≤10% 等价于每场景全部8个配对绝对变化≤10%。
   这是一项额外准入规则，不是总体诊断成本中位数上界<5%的逻辑必要条件。
   最新一轮还有中位界限失败，因此不能只删p90就说旧方案通过。
3. 四个条件依次“预热→正式”，即使跨面板平衡顺序，单个面板的版本比值仍会
   混入条件之间的时段漂移。旧方案固定label与实例启动顺序/端口的映射，也没有
   在面板间平衡这类位置因素。它们是可改善的设计因素，尚非已证实的全部根因。
4. 旧seed42只固定串行随机数，并行建图仍会改变；同索引大小不能证明同拓扑。
   接电和较低宿主负载也不能保证独占核心或固定频率。
5. 所以新一轮直接测量原版与三种诊断条件，改进面板内的顺序控制，继续使用
   严格的5%上界参考线。原脚本、旧失败和旧审计均保留，不宣称它们通过。

## 新协议：24 个独立新建实例面板，正逆序交叉

- 固定复用9/11统一工具链构建的原版/候选seed42镜像，以镜像ID及源码摘要核验。
  C/TAP候选不变。每面板四个私有实例，每次建索引新连接；同一时刻仅一个构建。
- 四条件：未修改原版、候选计时关闭、候选计时开启、开启并每秒只读观察。
- 四场景：串行/2 worker × spill/无spill。固定32维、m16、ef_construction64；
  spill为30,000行，串行1MB/并行4MB；无spill为100,000行、256MB。
  数据摘要必须一致，实际worker、spill与计时开关逐次核查。
- 24面板、固定seed20260912。每场景覆盖四条件全部24排列，随机打乱面板顺序；
  场景顺序覆盖全部24排列，实例启动/端口映射另行覆盖全部24排列。
- 每场景各条件先预热一次；正式按该面板排列正序、再逆序，各测两次。
  例如A B C D D C B A，每条件的位置中心相同，减少线性位置漂移。
  这不保证墙钟时间中心完全相同，也不能消除任意非线性漂移或热状态影响。
- 正式固定768次测量+384次预热。另一个smoke仅检验流程，不纳入正式统计，
  不根据smoke的性能比值选择条件、规模或统计方法。smoke使用一个同规模面板。
- 每实例2GiB、无额外swap、Linux客体CPU 0–9。不关闭其他项目服务、不改系统设置。
  接电、任务作用域防空闲休眠；逐次记录AC与双时钟。断电/休眠/构建失败时停止、
  保留失败、清理自有实例，不把中断前后的样本拼成完整通过结果。
- 正式运行期间不看累计效应来停止、改配置、追加面板或删样本。结束后无论支持
  与否都完整汇报。预估数小时，实际随宿主负载变化。

## 统计对象与判定（新定义，不能冒充旧协议）

对每个面板、场景和候选条件，计算两次完整SQL耗时的几何均值与该面板原版
两次耗时几何均值之比。重复测量用于减弱面板内噪声，**每组仍只有24个统计单位**。

主统计对象是这种“面板内两次几何均值配对比值”的总体中位数。它不是旧协议
单次配对比值的完全相同统计对象，也不是最坏单次开销或所有工作负载保证。

12个场景/条件比较的单侧上界使用二项分布顺序统计量，单项置信水平
1−0.05/12，Bonferroni家族误差率≤5%；n=24时取第19顺序统计量，且必须严格<1.05。
该推断以面板独立、可比较为前提；同一宿主的连续执行可能有残留时序相关，
不能将设计平衡等同于已证明这些假设。记录时间顺序和资源，结果中检查并披露。

完整通过还要求所有原始测量有效、192次正式观察均采到进度、实例身份与清理
核对通过。另报告独立的单侧下界用于区分“支持大于5%的回归”与“精度不足”；
上下两组分别控制家族误差，不把二者合称95%的双侧联合区间。

若某项上界未低于5%，保留未建立支持；不以点估计低于5%替代，不改门槛。
只有结果和代码证据能归因到具体C问题时才修改产品代码，不凭噪声制造补丁。

## 方法依据

分组和随机化用于控制干扰因素，参考 [NIST 随机区组设计](https://www.itl.nist.gov/div898/handbook/pri/section3/pri332.htm)。
本项目的正逆序重复是针对当前顺序问题的工程设计，不是该页面对本实验的背书。
中位数区间的二项分布/顺序统计量依据见 [NIST Median Confidence Limits](https://itl.nist.gov/div898/software/dataplot/refman1/auxillar/mediancl.htm)。
